## EPSG:32651 這串數字是什麼意思
在動公式之前先把代碼拆開。WGS84 的 UTM 分帶 EPSG 是有規律的：

```
326xx = WGS84 / UTM zone xx N（北半球）
327xx = WGS84 / UTM zone xx S（南半球）
```

所以 `32651` = 北半球第 51 帶。每帶寬 6 度，第 1 帶的中央經線是 -177°，於是：

```python
central_meridian = zone * 6 - 183      # 51 -> 123°E
```

南北半球的差別只有一個 `false northing`：南半球的 y 會加上 10,000,000 m，避免赤道以南出現負數。

```python
def zone_from_epsg(epsg: int) -> UTMZone:
    if 32601 <= epsg <= 32660:
        return UTMZone(epsg - 32600, north=True)
    if 32701 <= epsg <= 32760:
        return UTMZone(epsg - 32700, north=False)
    raise ValueError(f"EPSG:{epsg} 不是 WGS84 UTM 分帶")
```

## 逆投影的難點：足點緯度
UTM 是`橫麥卡托投影`，正投影（經緯度 -> 平面）有封閉解，逆投影`沒有`。

卡住的地方是子午線弧長。從赤道沿著子午線走到緯度 φ 的距離 M(φ) 是一個橢圓積分，級數展開之後長這樣：

```python
def _meridional_arc(phi):
    return A * (
        (1 - E2/4 - 3*E2**2/64 - 5*E2**3/256) * phi
        - (3*E2/8 + 3*E2**2/32 + 45*E2**3/1024) * np.sin(2*phi)
        + (15*E2**2/256 + 45*E2**3/1024) * np.sin(4*phi)
        - (35*E2**3/3072) * np.sin(6*phi)
    )
```

正向很好算，但逆投影要做的是`已知 M 反求 φ`，這個式子解不開。

標準做法是先假裝地球是球體，用 `mu = M / (子午線平均半徑)` 算出一個近似緯度，再用一組以扁率為參數的級數把它修正回橢球上，這個修正後的緯度叫`足點緯度（footpoint latitude）`：

```python
e1 = (1 - np.sqrt(1 - E2)) / (1 + np.sqrt(1 - E2))
mu = m / (A * (1 - E2/4 - 3*E2**2/64 - 5*E2**3/256))
phi1 = (mu
        + (3*e1/2 - 27*e1**3/32) * np.sin(2*mu)
        + (21*e1**2/16 - 55*e1**4/32) * np.sin(4*mu)
        + (151*e1**3/96) * np.sin(6*mu)
        + (1097*e1**4/512) * np.sin(8*mu))
```

足點緯度的物理意義是：`如果這個點在中央經線上，它會落在哪個緯度`。有了它就能在該點求出兩個曲率半徑，再沿著垂直中央經線的方向展開級數，把真正的經緯度湊出來：

```python
n1 = A / np.sqrt(1 - E2 * sin1**2)              # 卯酉圈曲率半徑
r1 = A * (1 - E2) / (1 - E2 * sin1**2) ** 1.5   # 子午圈曲率半徑
d = x / (n1 * K0)

lat = phi1 - (n1 * tan1 / r1) * (
    d**2/2
    - (5 + 3*t1 + 10*c1 - 4*c1**2 - 9*EP2) * d**4/24
    + (61 + 90*t1 + 298*c1 + 45*t1**2 - 252*EP2 - 3*c1**2) * d**6/720
)
```

公式抄自 Snyder 的《Map Projections: A Working Manual》，在分帶範圍（中央經線 ±3°）內誤差小於 1 mm。

## 接上管線：GeoJSON
有了經緯度就可以吐標準格式。RFC 7946 有三個坑：

**一、座標順序是 `(經度, 緯度)`**，跟中文講「經緯度」的順序一樣，但跟大家報座標習慣講的「25.08N, 121.23E」`相反`。寫錯的話點會跑到索馬利亞外海，而且不會有任何錯誤訊息。

**二、多邊形的環必須閉合**，第一個點要重複放在最後一個。

**三、外環必須是逆時針**（右手定則）。這一條在我們的情境下特別容易錯，因為：

```python
# 像素座標的 row 往下增加、經緯度的 lat 往上增加，
# 換算之後繞行方向會`翻面`，不能沿用像素空間的順序
area = sum(ring[i][0]*ring[i+1][1] - ring[i+1][0]*ring[i][1]
           for i in range(len(ring)-1))
return ring if area > 0 else ring[::-1]
```

另外畫地圖要用到反向轉換（經緯度 -> 像素），這裡也有個小坑，`GeoRef` 存的仿射矩陣是 `2x3` 不是方陣，沒辦法直接求逆，要補一列 `[0, 0, 1]` 湊成 3x3 齊次矩陣：

```python
m = np.vstack([georef.transform, [0.0, 0.0, 1.0]])
inv = np.linalg.inv(m)
```

## 小結
今天本來只是要把像素換成經緯度，結果換出三件事。

pyproj 跟 rasterio 一起被 Smart App Control 擋掉，而且擋在更前面的 `_compat.pyd`，所以 UTM 逆投影只能自己寫。寫這種級數展開最大的風險不是跑不動而是`默默算錯`，所以驗證疊了三層：往返只能抓打錯字，`子午線弧長用數值積分獨立算一次`才是真的在驗，最後對上公開的象限弧長常數 `10,001,965.729 m`，差 0.5 mm。
